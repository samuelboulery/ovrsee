démo interactive, rendue avec le code de l'app : cliquez une vue dans la colonne de gauche
Principe 01 Un plan, ses commits, ses tickets. Chaque décision approuvée dans Claude Code devient une ligne de projet : ce qui a été décidé, ce qui l'a exécuté, ce qui reste ouvert.
Principe 02 Le projet vit dans le dépôt. Backlog, historique et captures sous <repo>/ovrsee/, versionnés par git. Pas d'outil à tenir à jour en parallèle du code.
Principe 03 Claude Code y lit et y écrit. Serveur MCP et deux skills : l'agent connaît votre backlog, ouvre et déplace les tickets. Vous restez maître du plan.
Comment ça marche

Trois commandes, et le projet se tient à jour tout seul.

01 Installer, une fois par projet
$ pnpm ovrsee:install ./mon-projet
Pose les hooks Claude Code et le hook post-commit. Rien d'autre à configurer.
02 Cartographier l'application
$ pnpm ovrsee:crawl ./mon-projet
Playwright parcourt vos routes et photographie chaque écran, daté et rattaché au commit.
03 Lire
$ pnpm electron
L'application avec son terminal intégré, ou pnpm dev dans un navigateur, ovrsee:brief en texte.
Ensuite, c'est automatique : chaque plan approuvé dans Claude Code est capturé dans ovrsee/plans/, et le hook post-commit rattache chaque commit au plan actif.
Sept vues

Savoir où vous en êtes, sans ouvrir un seul fichier.

Aperçu Où en est le projet, en un écran : plans ouverts, tickets à faire, santé du dépôt, branches, déploiements.
Navigateur Votre app, ses DevTools et un sélecteur d'élément dans la fenêtre. Le sélecteur se colle directement dans Claude.
Produit Le graphe des pages crawlées, miniatures à l'appui. Deux dates se comparent : ce qui a changé se voit.
Historique Ce qui a avancé, semaine après semaine : chaque commit sous le plan qui l'explique, l'activité en un histogramme.
Tableau Le backlog, en kanban : epics et avancement, limites de WIP, un fichier markdown par ticket que Claude sait écrire.
Données & Stack Tables, colonnes et qui s'en sert ; dépendances avec la raison écrite en commentaire WHY: au-dessus de l'import.
Avec Claude Code

Claude reste dans la boucle, vous gardez la main.

01 Terminal intégré
Un vrai pty : shell de connexion, claude lancé dedans, plusieurs sessions, dock en bas, sur le côté ou plein écran. Les commandes du projet (crawl, graphe, export Obsidian) sont à un clic. Réservé à l'application, et par IPC : l'exposer sur une socket locale l'ouvrirait à tout processus du même compte.
02 Deux skills livrées
ovrsee apprend à lire ovrsee/ : plans, pages, scans, captures et leurs pièges de lecture. ovrsee-tickets apprend à écrire les tickets du tableau, format et gestes compris. Installables depuis l'écran d'initialisation, ou avec --skills.
03 Serveur MCP
stdio, JSON-RPC 2.0, même interface que /api/* : Claude lit tout ovrsee/, n'écrit que les tickets et board.json, n'exécute aucun code. Seuls les projets du registre sont lisibles : un chemin absent est refusé, même s’il existe sur le disque.
L'onglet Données lit le graphe de code produit par Graphify : parsing AST local, chaque relation étiquetée. Ovrsee ne recalcule rien : il détecte l'outil et affiche sa commande.
Le projet, en fichiers

Votre backlog vit dans votre dépôt.

Tout le suivi du projet tient dans un dossier de votre dépôt : il suit les branches, se relit dans un éditeur, s'exporte en coffre Obsidian avec ses wikilinks. Pas de format propriétaire, aucun outil à synchroniser.
